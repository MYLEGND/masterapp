## Authoritative flow and direct repairs

CONFIRMED: all platforms use the existing authenticated `MessagingHub.Call` → `ILegendCallingAuthority` → `MessagingService` → `LegendCallSessions`/signal outbox. No new call server, identity store, provider, endpoint, push authority, or policy router was introduced. Client adapters own OS/media integration, not recipient authorization or call decisions.

1. Calling resolves the existing typed authenticated actor and device. The backend reuses conversation membership, account validity, privacy/block rules, single-answer device binding, epoch validation and bounded call leases. Push dispatch is never treated as delivery; only recipient presentation records `ReceivedUtc`.
2. iOS previously awaited a weak call owner created behind authenticated/localization UI, including a three-second preparation poll. The retained canonical Keychain account now prepares the same call/message store through existing token refresh and server bootstrap without unlocking the app UI. Normal startup still requires the existing biometric gate; account revision fencing prevents late wake/restore results from crossing sign-out or account changes. CallKit is reported promptly and answer preparation is bounded by its action deadline.
3. Android's same existing call lifecycle/overlay now initializes independently of localization readiness, inside authenticated ownership. Notification actions are call-specific and nonce-bound. Permission receipts bind call, device and owner through Activity recreation and the existing unexported foreground service; a grant or denial from call A cannot answer, terminate or share into call B.
4. Outgoing progress audio no longer waits for recipient receipt. Existing CallKit/Telecom audio ownership remains required; there is no fake connected state. Calling/Ringing labels still reflect actual delivery, and recipient identity is visible. Audio/media clean up on cancellation, failure, replacement, logout and completion.
5. The shared web messaging shell previously had no WebRTC calling adapter. Its new platform adapter uses the same existing SignalR connection and `Call` command. It supports raw SDP, device/epoch-bound ICE, single-flight media acquisition, cancellation compensation, monotonic snapshots, bounded connection/recovery deadlines, aggregated remote tracks and explicit autoplay recovery. Stale ICE generations are checked against local SDP ufrags. Sign-out immediately and irreversibly retires media/UI, broadcasts same-origin retirement with storage fallback, and stops the socket independently of acknowledgement. A restored back/forward-cache document reloads through authentication. The shared hub closes at credential expiry.
6. Branded shared web/native call screens show the peer's canonical protected profile photo or default presentation. Wallpaper mode always follows the peer, not the local caller. Two existing bundled LEGEND tones are selectable. The existing `MobileProfileSettings` typed ProfileId row owns `CallRingtoneId` and `CallWallpaperMode`; all devices read/write through the same `Call` preferences command. The backend returns validated choices, resource names, and effective snapshot presentation. Both peer preferences are retrieved together to avoid repeated profile/settings reads per heartbeat. Existing profile fields and retained translations are preserved.
7. Existing notification photo capabilities were precisely extended to both call participants with per-recipient typed grants, expiry and current membership/call rechecks. Native uses this existing endpoint. Both web hosts reuse their existing authenticated `/Messaging/Participants/.../Avatar` endpoint, rather than assuming the mobile API exists on ClientApp. No copied image or arbitrary URL fetch is admitted.
8. iOS app-only `RPScreenRecorder.startCapture` was replaced by a real ReplayKit broadcast extension feeding the existing RTC video source through bounded App Group socket frames. Each active sharing session uses a random nonce, one-frame acknowledgement, JPEG size/FPS limits and cancellation. Pixel data is owned before ReplayKit returns its sample buffer. No media archive or authentication token is copied into the extension. Android requests whole-display capture on supported versions using the existing OS consent flow. Browser sharing uses fresh user-authorized `getDisplayMedia`; it cannot force an OS screen selection.
9. Browser media now consumes the shared camera/adaptation/screen-share policy. Selected transport stats drive immediate downgrade and consecutive-valid-sample recovery. Failed/missing stats cannot prove recovery or discard a measured audio reservation. Screen video budgets subtract audio and transport headroom; zero budget pauses video. Shared maximum dimensions/FPS preserve aspect ratio, camera policy returns on stopping sharing, and delayed observations cannot affect another call. Native adaptation remains its existing policy consumer. Network type unavailable to a browser is not measured Wi-Fi/cellular evidence.
10. The existing copy catalog generator now extracts calling errors and recognizes both JavaScript quote styles. Preset quota notice translations remain retained. Two prior translation tests still expected a successful original-only page on generic provider failure, although production source was unchanged since baseline and returns `MESSAGING_TRANSLATION_NOT_READY`. Tests now enforce that contract, preserve originals/no false cache/read-boundary safety, and prove successful recovery and quotation cache reuse. Quota denial still delivers the original plus its preset notice; no production translation fallback was changed.

## Persistence, compatibility and rollback

Migration `20260913193539_AddCallingProfilePreferences` adds exactly two non-null 32-character columns with `signature`/`legend` defaults to the existing settings table. It was generated offline through the existing design factory with a localhost design-only connection; no database was contacted or updated. No call/history/media records were deleted. Older installed clients can ignore additive wire fields.

Photo wallpaper currently reuses the account's existing profile picture and editor; there is no separate arbitrary wallpaper upload store. Ringtone selection uses bundled assets; adding a new sound requires a compatible native build. OS-level ringtone/notification settings remain under user control.

Rollback is code-version rollback with the additive columns retained. Do not run destructive Down migrations or discard profile preferences as part of rollback. Keep the previous signed mobile build and backend artifact available before a later release. The new native behavior requires distributing new iOS and Android builds; backend deployment alone cannot deliver it.
